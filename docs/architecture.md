# 平台架构

枝序采用同仓库、按平台目录划分的结构。macOS 原生版已实现；新增独立 Flutter 双端原型，验证共用界面与 Git 流程，尚未替代正式版。

## 当前实现

`apps/macos` 是 Swift Package。SwiftUI/AppKit 负责界面与编辑器，本机 Git 负责仓库操作，钥匙串和 Git 凭据助手负责认证。集成测试以临时仓库验证操作结果和数据保护。

目前 Git 操作编排与平台支持仍在 Swift 工程中，不宣称存在可直接用于 Windows 的公共核心。

## Flutter 双端原型

`apps/flutter_prototype` 包含共用 Dart 界面和 Git 服务，以及 macOS / Windows 平台工程。按原生模块逐项移植工作台、编辑器、分支、历史、备份、冲突与认证；对照状态见 [PARITY.md](../apps/flutter_prototype/PARITY.md)。原生 `apps/macos` 保持不变。详见 [原型说明](../apps/flutter_prototype/README.md)。Windows 发布状态仍为未上线，不能把已有平台目录视为实测通过。

## Windows 边界

复用品牌素材、功能规范、测试案例和用户文档。Windows 仍需适配文件路径、大小写规则、符号链接、进程取消、凭据存储、输入法、快捷键和安装更新。

Git 命令语义可以参考 macOS，但不能照搬平台行为；特别需要验证换行符、中文路径、大小写重命名和文件占用。当前优先在 Flutter 原型的 windows 平台工程中验证，不再预设必须另写一套完整 Windows 原生界面。

## 共同约束

- 默认只提交用户勾选的文件，不隐式提交其他已暂存修改。
- 刷新保留未保存的编辑缓冲区和有效勾选。
- 危险操作确认后再次验证状态，避免覆盖确认期间产生的新修改。
- 优先复用系统 Git 认证，仅在需要时提示登录。
- 分支切换、恢复备份和合并保留明确的取消或恢复路径。

分支用于功能开发与合并，平台由目录区分。需要独立发布时可使用 macos-vX.Y.Z、windows-vX.Y.Z 标签；两端共同发布时可使用 vX.Y.Z，但发行说明须准确列出实际提供的平台。
